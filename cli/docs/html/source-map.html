Petri CLI Source Map

Ownership map for the Rust CLI/TUI. Use this before splitting work across agents or worktrees.

Modules

Path Owns Change Notes
src/cli.rs Public command grammar, global flags, help text. Keep user-facing commands aligned with the web product and public CLI theory of mind.
src/main.rs Command dispatch, plain/JSON output, the front door and help sheet, and config show. Route market and trading commands through futures::run into futures::reads and futures::trade, and oracle commands through oracle::run; no business logic here.
src/futures/mod.rs Futures, the product the site trades: the trusted futures program, market resolution by symbol, name or address, loading a market account from chain and checking it (owner, USDC mint, oracle program), the owner's funds, order evaluation against the book (fill, netting, deposit needed), the submit plan, and money helpers. A market account must belong to the deployment's futures program, settle in its USDC and read its oracle. Orders are solved with the futures client crate's proposer; a stale proposal is solved again once.
src/futures/api.rs The futures API client: /v1/config, sponsored prepare and submit, the faucet, and the views of /v1/markets (markets, one market, depth, trades, candles, index), /v1/quote and /v1/accounts (an owner's account and history). Atom amounts are strings; *Value fields are index values. API data is never trusted for what gets signed.
src/futures/shape.rs Range, leverage and limit math ported from the web ticket: --range parsing, leverage to the losing-side end, the suggested range or --to for the winning side, premiums, slippage limits, and lots for a --usd budget. Keep it equal to web/src/lib/futures/market.ts so the CLI and the site send the same order for the same inputs.
src/futures/reads.rs markets, market, book, trades, chart, positions, history and wallet. Reads need no wallet; owner reads take an address.
src/futures/trade.rs quote, long, short, close, cancel, deposit and withdraw, and the local and sponsored send of each. Orders, closes and cancels have a prepare step (prepare_open, prepare_close, prepare_cancel: priced and reviewed) and a send step (send_open, send_close, send_cancel) that the commands and the TUI's Markets view share. Quote first and confirm unless --yes. A market order sends at most the quoted fill with the --slippage limit; auto picks local at 0.01 SOL or more.
src/futures/check.rs The sponsored-transaction check: sponsor as fee payer, only the compute budget, the owner's own USDC account creation and the trusted futures program, this market only, the owner's own token account, exactly the requested order, and a deposit bounded by what the order can need. Runs before the owner signs any sponsor-prepared futures transaction; tests tamper with each field.
src/futures/ (shared) ctx (per-command context), settings (flag, config file, then the profile's defaults: production, a release build's default, or dev, the default of a dev-chain build), market (the trusted deployment, held to the production ids in the production profile, and name resolution), rpc, api (above), txbuild (named plans, the compute budget, the owner's USDC account), exec (local and sponsored sending, confirmation), governance (controller gate epochs for each governed target), error (futures, governance and token error names and hints), view, units, ops (wallet new, wallet address, status), funds (the faucet, dev-faucet builds only). Every signing path goes through exec, which calls the identity gate and binds governance gates first.
src/oracle/mod.rs The index oracle: args grammar, reads (futures API oracle documents and candidates), chain (periods, months, sources, ledgers read and checked from chain), skus (governed SKU sets, part numbers and chip buckets, and Merkle proofs), series (comparison series of the chip months: template, check, propose, show; the commodity spec's routing of a month's sources, shared with the TUI), observe (observations of a series: its opening print or Game update, and its record with the API), send (identity, the oracle's own governance gate, review, simulate, sign, send), writes (one handler per instruction), sponsor (sponsorships), rewards (a wallet's rewards read from chain and their tag 174 claims), council (emergency council cases), claims (private update-claim reveal material), errors (oracle error names). Build instructions only with ameba_oracle::instruction builders against the deployment's oracle id. Decode every account through chain::decode and check its canonical address and parent. council reads current council rosters, case commitments and round ballots before building a council decision.
../oracle/governance/ The governed RAMX and NANDX product SKU manifests (v1 part numbers, v2 chip buckets) and the commodity submission spec, compiled in from the monorepo's oracle (v2 and the spec through ../oracle/crates/commodity-spec). Tests pin their roots to the oracle program's; they change only with the oracle.
src/chain_identity.rs Deployment identity gate: genesis, deployed oracle and futures programs, oracle config and bond mint. Every signing path calls it before loading a signer. Cached once per process.
src/endpoints.rs The futures API's oracle routes and query encoding. Futures routes live in src/futures/api.rs.
src/backend.rs Terminal-safe text and JSON output. Every printed field passes through it.
src/wallet_signer.rs, src/onchain.rs, src/solana_config.rs Keypair and hardware-wallet loading, file-permission checks, Solana CLI config. Never print keypair contents; MCP processes cannot sign.
src/chart.rs Terminal chart rendering: candle closes as an ASCII plot with volume. futures::reads::chart fetches the candles.
src/research/mod.rs Terminal UI: the Markets and Bots views and the oracle research tabs Connect, Activity, Evidence and Rewards. Rendering stays free of network and storage effects.
src/research/intro.rs The TUI's introduction: amoebas crawling as ASCII tiles on a light page, a frosted glow, the wordmark and "click to start". Shown on every interactive start while the first reads run; a click, Enter or Space starts. Amoebas crawl by pseudopods and steer clear of each other. Draws only, deterministic for a seed and time: petri tui --render 100x30 --view intro --at 3 prints a frame. No loading text. Each frame starts from a cached still layer and quantized shades, so the terminal is sent only what moved (the ignored test bench_frames measures it).
src/research/markets.rs TUI Markets view: the market list, the book of the suggested range (as petri book), trades, the index and price, the account's positions and orders, and long, short, close and cancel tickets. Owns no trading logic: tickets call futures::trade's prepare and send steps, quote before y sends, and use the CLI's 2% slippage default. The leverage keys step through the site's leverages that fit the market's price.
src/research/bots.rs TUI Bots view: the bots in petri's bots/ folder, start (after a yes) and stop, weights edited in place, a new ladder bot for a picked market. Its worker owns the bot host: it picks up a running bot's file edits, reads the bots' markets every two seconds, runs them and sends what they propose. petri bots (write, read, remove, publish, discover, show, install, leaderboard) and petri bots serve (JSON lines) drive the same worker without a terminal, and a running bot's lock in bots/.locks/ keeps one bot to one petri. Starting a bot funds its own wallet up to its budget and registers its run; each look it reads the bot's wallet, moves a product bot to its next month and brings old months' cash home; stopping it sweeps the bot wallet's USDC back. bots/.running restarts running bots with the next worker. The contract is docs/bots.md. Owns no trading logic: bots propose, bots::send checks, signs (with the bot's wallet) and sends. Stopping a bot or quitting petri takes its ladder down first; updates wait while a bot runs.
src/compose/ The runtime bots run on (Cordis's model, arXiv 2608.25512): components inject and provide keys; every effect is kept with its inverse; a component runs while what it injects is provided and is undone when it goes; realms keep subtrees apart; loader.rs reconciles rows by id. No network, storage or UI. Synchronous: one transition at a time, each to completion. compose/tests.rs checks the paper's properties one by one.
src/bots/ Trading bots: bundle files (bundle.rs), the host's keys and feeds (keys.rs, feeds.rs), the parts (weights.rs, signals.rs, ladder.rs: the house maker's ladder for one wallet, fitted to the book's room; script.rs: strategy/script, a Rhai script in a sandbox of pure packages with a 5,000,000-operation limit a tick), the host (host.rs), each bot's own wallet and its funding and sweep plans (wallet.rs), the futures API's bot registry and GitHub files (registry.rs) and the network side (send.rs: reads, sends through futures::trade's order paths, settling and sweeping old months). Parts never see a key, signer or client. send.rs reads the market fresh from chain, checks post-only and the program's ladder-arc count before any cash moves, and sends on the local route through exec::send_local. The ladder math is the futures client's pricing, shared with futures-maker.
src/research/nav.rs, src/research/research_page.rs TUI Research view: the navigator (products, months, categories, one category's tasks) built from the oracle's months (phase.rs) and the workspace's work in them, each agent's feed, and following an agent's work; research_page.rs draws it beside the agent's page. Displays only: its writes are the owner's Research this, Stop researching and Directive (/v1/owner/work/focus, /v1/owner/work/refine).
src/research/agent/ An agent's research commands and its MCP server (petri research agent|session|work|activity|rewards|mcp), the workspace's only research MCP. Talks only to the local workspace service; submits source candidates through it, never to the chain.
src/research/service/, src/research/workspace.rs The workspace service (petri research serve, a detached petri process) and its owner commands: workspace.sqlite, sealed credentials, the /v1 routes, and the ping and restart handover that lets a newer petri replace an older one on its port. Passes the futures API as the candidate store and oracle read endpoint. Private state stays outside application code.
src/research/updates.rs Automatic preview updates at startup and every six hours. Wait for 30 idle seconds with no open form or request.
src/release_update/ Preview release validation, bounded extraction, staging, replacement and recovery. On Windows a running petri.exe is moved aside, not overwritten, and the leftover is deleted later. Never execute downloaded scripts or touch wallets, config or agent registration.
src/workspace_update.rs Source-checkout updater. Fast-forward only to an explicitly trusted commit.
src/agent_protocol.rs petri mcp manifest: how agents connect to Amoeba's hosted MCP server (the futures API's /mcp). Names the URL, each assistant's entry and the signing boundary; the tools are the server's.
src/read_only.rs PETRI_MCP_READ_ONLY=1: petri run by an agent. No key read, no signing, no update.
src/mcp_setup.rs Registers the hosted MCP server by URL in Claude Code and Codex: status, enable, repair, disable. Changes only its own petri entry (an Amoeba API's /mcp, or the old local server's marked entry, which repair replaces and whose files it removes); preserves unrelated settings.
scripts/petri-launcher.mjs Repo-local delegation to the Rust binary and installation/update work. Implements no product command.
scripts/package-petri-*.{ps1,sh}, scripts/package-petri-preview.mjs Release and preview packaging. Signed installers remain separate.
scripts/generate-third-party-licenses.mjs The lockfile-bound license corpus. First-party Amoeba crates are listed without a third-party license.

Research Workspace Boundaries

  • main dispatches tui and research first. The Markets view builds its own futures context from the shared src/futures/ code.
  • src/research/ owns the terminal session and layout; UI code reads state and emits intent, and its worker performs authenticated local HTTP requests.
  • The Bots view's worker (src/research/bots.rs) is separate: it runs the bot host and sends only through bots::send.
  • src/research/service/ owns private local research state. The futures API's candidate store is the authority for submitted candidates.

External Contracts

  • The futures API (--api, contract in ../api/API.md) serves the market views under /v1/markets, /v1/quote and /v1/accounts (markets, depth, trades, candles, quotes, accounts and history), sponsored preparation and submission, the dev faucet, the hosted MCP server at /mcp (what petri mcp enable registers), the oracle documents /v1/oracle/public-snapshot and /v1/oracle/catalog, the candidate store at /oracle/agents and /oracle/source-candidates, and the observation records at /oracle/observations (petri oracle observe).
  • The Solana RPC (--rpc) serves account reads, simulation and sending.
  • Program ids come from the trusted deployment (--deployment manifest, else the API's /v1/config).
  • Futures instructions come from the futures client crate (ameba_sdk_futures::futures); oracle instructions, PDAs and layouts from the ameba_oracle crate of the monorepo (../oracle, a path dependency in Cargo.toml).
  • MCP setup owns only its own petri entry in ${CODEX_HOME:-$HOME/.codex}/config.toml and $HOME/.claude.json, registers a URL, and runs nothing locally.

Validation

Futures tests check order shapes, limits and budgets against the web ticket, parse the documented API views, and tamper with every field of a sponsored transaction to prove the check refuses it. Oracle tests pin the governed SKU roots, check Merkle proofs against the program's verification, error names against the crate's variants, evidence commitments against the program and the candidate store, and the grammar of every command. MCP setup tests cover registering, repairing (from the old local server too) and removing the entry without touching other settings; the hosted server's tools are tested in the API. Bot tests check the runtime's properties (compose/tests.rs) and the ladder.

Run scripts/devloop.sh before handing off code. Run scripts/check-petri-launcher.mjs and scripts/check-petri-packaging.mjs when changing launcher or app packaging. For visible TUI changes, also run the native Windows ConPTY harness or the documented Unix PTY smoke. Live checks against the dev localnet are described in localnet-dev.md.
