Capped Futures

Petri trades the capped futures the website trades: markets, book, trades, chart, quote, long, short, positions, close, cancel, deposit, withdraw and history. A position is a range of the index; what it costs up front is the most it can lose.

Reads and quotes come from the futures API's /v1/markets, /v1/quote and /v1/accounts views. Orders are solved against the market account read from chain (local route) or prepared by the API's sponsor and checked before signing (sponsored route). See the command guide.

Index Oracle

petri oracle reads the standalone oracle's months, sources, catalog and research candidates from the futures API. Writes (collateral, evidence, sources, opening prints, Game updates, escrow settlement, council disputes) are built with the ameba_oracle crate against the deployment's oracle program and signed by the attached wallet; --simulate runs them unsigned. See the command guide.

MCP

Users can run petri mcp enable, or connect from Home > Connect your AI agent and select Enable Petri MCP. No manual server process or operating-system startup service is required.

Petri MCP is read-only: futures markets, charts, books, trades, quotes, positions, balances and history, and the oracle's months, sources and candidates. Trades and oracle writes run only in the user's terminal. Owner-scoped reads require an explicit owner public key, and every wrapper child carries a Rust-enforced read-only signer boundary.

Setup lifecycle, tool names and the signing boundary live in mcp-agent-protocol.md.

Runtime Shape

Standalone preview updates: see the update command guide and source map. Downloaded preview apps use src/release_update/; source builds retain the Git/Rust updater.

  • petri prints the front door; petri help lists every command; petri tui opens the terminal interface.
  • Petri talks to one Solana RPC (--rpc) and one futures API (--api); program ids come from the API's /v1/config or a trusted manifest (--deployment).
  • Orders are solved with the futures client crate against the market account read from chain and sent through RPC with the wallet as fee payer, or prepared by the futures API's sponsor and checked by src/futures/check.rs before signing.
  • Oracle reads come from /v1/oracle/public-snapshot, /v1/oracle/catalog and /oracle/source-candidates; oracle accounts used for writes are read from the oracle program and checked before use.
  • src/chain_identity.rs verifies the cluster (genesis), the deployed oracle and futures programs, and the oracle config's bond mint before anything is signed.
  • petri tui's Markets view lists the markets and trades, closes and cancels through the same prepare and send steps as petri long, petri close and petri cancel.
  • The research workspace stores candidates in the futures API's candidate store and reads the same oracle documents.
  • petri --json mcp manifest publishes the MCP/tool wrapper contract.
  • scripts/petri-launcher.mjs only delegates to Rust or performs installation/update work.

Core Rule

Keep the terminal user-facing and product-compatible with the website. Read indexed data from the futures API and account state from the chain; build every transaction with the program crates and check it before signing.

Public command names, help text, JSON, and MCP tools should use product nouns such as markets, book, trades, chart, quote, long, short, positions, close, wallet, history, and oracle. Do not expose admin, operator, internal, route, database, matcher, bootstrap, or payload grammar through the public Petri surface.
